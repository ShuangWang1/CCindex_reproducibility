# External input manifest

Run commands from the repository root. Obtain study inputs through their original data providers and retain their applicable access terms. This release does not redistribute inputs or provide an automatic downloader.

| Input | Expected local path | Use |
| --- | --- | --- |
| AD target graph | `spatial_13months-disease-replicate_1.gml` | AD benchmark and both ablations |
| AD base-triangle frequencies | `ad_data.csv` | Initial motif vocabulary; columns encode three cell types separated by `&`, with counts in the first data row |
| BZ AnnData | `breast_cancer/BZ.h5ad` | Graph preprocessing; core/sample linkage |
| METABRIC AnnData | `breast_cancer/metabric.h5ad` | Graph preprocessing; image/patient linkage |
| BZ clinical table | `breast_cancer/Basel_PatientMetadata.csv` | Patient linkage, overall survival, and clinical covariates |
| METABRIC clinical table | `breast_cancer/41586_2019_1007_MOESM7_ESM.txt` | `METABRIC.ID`, follow-up `T` in days, and `Death` |
| METABRIC data dictionary | `breast_cancer/41586_2019_1007_MOESM10_ESM.xls` | Documents clinical endpoint definitions |
| Grade/sample linkage files | `breast_cancer_classification_workstation/bz_grade.csv`, `breast_cancer_classification_workstation/meta_grade.csv` | Existing sparse-artifact preparation commands |

The AnnData converters expect dataset-native sample identifiers, spatial coordinates, one-hot `obsm['node_types']`, and `uns['node_type_names']`; inspect `breast_cancer_preprocess_intra.py --help` and the converter checks before running. BZ uses `core`; METABRIC uses `ImageNumber`. Use the dataset-native converter for these case studies so cell types are not merged between cohorts.

Grade linkage CSVs have columns `id` and `grade`; the retained preparation code decodes one-hot grade strings. They are used to reconstruct the historical sample inventory, not as survival outcomes. Supply the original linkage files to reproduce that inventory; do not infer missing grades or patient identifiers. The sample manifests and cell-type mapping CSVs are generated by preprocessing.

## Regenerated artifacts

Graph preprocessing writes `breast_cancer/BZ_samples_intra/` and `breast_cancer/metabric_samples_intra/`, including manifests and label mappings. Motif mining writes per-sample frequency CSVs and run summaries beneath `breast_cancer_meta/`. The artifact preparation commands then produce sparse matrices, feature vocabularies, and sample inventories.

Default BZ sparse artifacts are stored under `breast_cancer_classification_workstation/classification_by_level/mtf_occurrence/mrmr_selection/parameter_tuning_bz/artifacts/tri_N/`. Default METABRIC artifacts are stored under `breast_cancer_classification_workstation/artifacts/metabric/`. These layouts are preserved because downstream tools reference them.

Existing external artifacts can be supplied instead of regenerating them. Keep matrices, row-order/sample tables, motif vocabularies, mappings, and clinical records from the same run. Do not combine historical count matrices with a partial rerun.
